## Etapa 1 — Extração do crate `lemon-widgets` *(fundação de todo o resto)*

### 1.1 Workspace

- Adicionar `crates/lemon-widgets` em `[workspace] members` no `Cargo.toml` raiz
- Criar `crates/lemon-widgets/Cargo.toml` com `lemon = { workspace = true }` e `publish = true`

### 1.2 Refatorar `Element` enum no core

Arquivo: `crates/lemon/src/element/mod.rs`

- Renomear/reorganizar variantes para primitivas puras:
  - `Box` → `Prim { style: StyleProps, paint: PaintProps, children: Vec<Element>, handlers: EventHandlers }`
  - `Text` → `TextNode { content: TextContent, style: TextStyle }`
  - `Component`, `Fragment`, `None` permanecem iguais
  - Remover variantes `Row`, `Column`, `Button`, `Image` do enum core
- Atualizar diff (`crates/lemon/src/diff/`) para usar as novas variantes
- Atualizar retained tree (`crates/lemon/src/retained/`) para usar as novas variantes
- Atualizar layout pass (`crates/lemon/src/layout/`) — Row/Column eram Prim com flex; agora `Prim` sempre usa `StyleProps.display: flex` quando configurado
- Atualizar paint pass (`crates/lemon/src/paint/`) — `Button` era Prim com paint + label; agora é composição em lemon-widgets

### 1.3 Criar builders em `lemon-widgets`

Arquivos novos em `crates/lemon-widgets/src/`:

- `lib.rs` — re-exporta tudo
- `row.rs` — `Row` builder: retorna `Element::Prim` com `display: flex, flex_direction: row`
- `column.rs` — `Column` builder: retorna `Element::Prim` com `display: flex, flex_direction: column`
- `box_.rs` — `Box_` builder: retorna `Element::Prim` genérico
- `text.rs` — `Text` builder: retorna `Element::TextNode`
- `button.rs` — `Button` builder: retorna `Element::Prim` com paint de background, padding e `on_click`
- `image.rs` — `Image` builder: retorna `Element::Prim` (placeholder até V0.4)

### 1.4 Atualizar exemplos

- `examples/counter/src/main.rs`: trocar `use lemon::widgets::*` por `use lemon_widgets::*`
- Verificar que `cargo run -p counter` continua funcionando

## Etapa 5 — Keyboard

**Depende de:** Etapa 1 concluída.

### 5.1 Tipos de evento

Arquivo: `crates/lemon/src/element/events.rs` (ou `event.rs`)

```rust
pub struct KeyEvent {
    pub key: Key,          // winit::keyboard::Key re-exportado ou wrapper
    pub modifiers: Modifiers,
    pub repeat: bool,
}

pub enum KeyboardHandler {
    KeyDown(Rc<dyn Fn(KeyEvent)>),
    KeyUp(Rc<dyn Fn(KeyEvent)>),
}
```

- Adicionar `on_key_down` e `on_key_up` em `EventHandlers` do retained tree
- Adicionar `.on_key_down(f)` e `.on_key_up(f)` em `Prim` builder

### 5.2 Sistema de foco

Arquivo: `crates/lemon/src/retained/focus.rs`

- `FocusManager`: mantém `Option<NodePath>` do nó com foco atual
- Prop `focusable: bool` em `StyleProps` (padrão `false`)
- `FocusManager::next()` / `prev()` para Tab / Shift+Tab — percorre retained tree em ordem de documento, filtrando `focusable: true`
- `FocusManager` vive no `AppState` (platform layer)

### 5.3 Platform — despacho de eventos de teclado

Arquivo: `crates/lemon/src/platform/window.rs`

- Processar `WindowEvent::KeyboardInput` do winit
- Se `Tab` → `FocusManager::next()` (ou `prev()` com Shift)
- Senão → despachar `KeyEvent` para `on_key_down` / `on_key_up` do nó focado

## Etapa 6 — Hover

**Depende de:** Etapa 1 concluída.

### 6.1 Estado de hover no retained tree

Arquivo: `crates/lemon/src/retained/mod.rs`

- Campo `hovered: bool` em `RetainedNode`
- `hoverable: bool` em `StyleProps` (padrão `false`; `true` quando `on_hover_enter` ou `on_hover_leave` definido)

### 6.2 Handlers

- Adicionar `on_hover_enter: Option<Rc<dyn Fn()>>` e `on_hover_leave: Option<Rc<dyn Fn()>>` em `EventHandlers`
- Adicionar `.on_hover_enter(f)` e `.on_hover_leave(f)` em `Prim` builder

### 6.3 Platform — hit-test de hover

Arquivo: `crates/lemon/src/platform/hit_test.rs`

- Manter `Option<NodePath>` do nó atualmente hovered em `AppState`
- A cada `CursorMoved`: hit-test pós-ordem sobre nós `hoverable`
- Se mudou: disparar `on_hover_leave` no nó anterior, `on_hover_enter` no novo

### 6.4 Cursor do sistema

- Prop `cursor: CursorIcon` em `StyleProps` (padrão `Default`)
- A cada `CursorMoved`: aplicar `cursor` do nó hovered via `winit::window::Window::set_cursor`
